## 설치

처음 한 번만 합니다. 터미널(응용 프로그램 › 유틸리티 › 터미널)을 열고 차례로 입력합니다.

1. 생성기 폴더로 옮겨 갑니다. `/경로/`는 저장소를 둔 곳으로 바꿉니다.

   ```bash
   cd /경로/hanok_window/generator
   ```

2. 이 폴더 전용 파이썬 환경(`.venv`)을 만듭니다. 컴퓨터의 다른 파이썬 프로그램에는 영향이 없습니다.

   ```bash
   python3.11 -m venv .venv
   ```

3. 검증한 버전의 의존 패키지와 생성기를 설치합니다.

   ```bash
   .venv/bin/python -m pip install -r requirements.lock
   .venv/bin/python -m pip install -e .
   ```

4. 설치를 확인합니다. 도움말이 나오면 끝입니다.

   ```bash
   .venv/bin/hanok-window --help
   ```

`requirements.lock`은 CPython 3.11로 Windows 11(AMD64)과 GitHub Actions의 ubuntu 24.04·macOS 26(arm64)에서 검증한 버전 목록입니다. 저장소를 새 버전으로 받은 뒤에는 3번의 두 번째 줄(`pip install -e .`)을 다시 실행해야 화면에 새 버전이 표시됩니다.

## 켜고 끄기

**Finder에서:** generator 폴더의 `web-start.command`를 두 번 누릅니다. 터미널 창이 열려 서버를 켜고, 기본 브라우저가 http://127.0.0.1:8765 를 엽니다. 터미널 창은 닫아도 됩니다. 다 쓰면 `web-stop.command`를 두 번 눌러 끕니다.

**터미널에서:** generator 폴더에서 `web.sh`를 씁니다.

```bash
./web.sh start      # 켜고 브라우저로 엽니다
./web.sh status     # 켜져 있는지 봅니다
./web.sh stop       # 끕니다. 진행 중인 생성은 끝까지 기다립니다
./web.sh restart    # 껐다가 다시 켭니다
./web.sh log        # 서버 기록의 마지막 40줄
```

켜지면 이렇게 알려 줍니다.

```text
켜졌습니다: http://127.0.0.1:8765
끄려면 ./web.sh stop (Finder에서는 web-stop.command)
```

- 서버는 이 컴퓨터에서만 열립니다. 같은 네트워크의 다른 컴퓨터나 휴대폰으로는 접속할 수 없습니다.
- 브라우저나 터미널 창을 닫아도 서버는 계속 켜져 있습니다. 다 쓰면 끄세요.
- 다른 포트로 켜려면 `./web.sh start --port 8800`, 브라우저를 열지 않으려면 `--no-open`을 붙입니다.

## 설계하기

### 화면 구성

<img src="images/design.png" width="960" alt="설계 화면. 왼쪽에 입력, 가운데에 정면도, 오른쪽에 요약과 패키지 생성 단추가 있다">

처음 열면 R3 예제(양문, 외경 463 × 586 mm, 창살 2+4, A3 그림)가 들어 있습니다. 왼쪽 **입력**을 바꾸고 0.15초가 지나면 서버가 설계를 해석해 가운데 **미리보기**와 오른쪽 **요약**을 새로 그립니다. 위쪽의 **설계**와 **기록**으로 화면을 바꿉니다.

### 입력

<img src="images/design-inputs.png" width="310" alt="입력 칸: 창 형식, 크기, 창살, 프리셋, 그림과 뒤판, 원판, JSON 단추">

| 묶음 | 하는 일 |
|---|---|
| 창 형식 | **양문**(좌우 두 짝, 두 짝 모두 바깥쪽 선대에 경첩) 또는 **단문**(한 짝) |
| 크기 | **외경**, **내경** 또는 **화판**(액자형) 기준의 가로 × 세로(mm) |
| 화판 · 액자형 | 크기 기준이 **화판**일 때만 나타납니다. 화판 두께, 고정틀이 덮는 폭, 끼움 여유, 스페이서 두께(mm) |
| 창살 · 창짝당 | 한 짝에 들어가는 세로·가로 창살 수. −/+ 단추나 직접 입력으로 바꾸고, 0개도 됩니다. 아래에 빈칸 크기와 교차 수가 나옵니다 |
| 프리셋 | `standard_v1`(기본), `hanok_A3_portrait_R3`(R3 규칙: 양문 전용, 창짝 높이/폭 2.6 이상, A3 그림 기본) 또는 `standard_4x8_v1`(`standard_v1` 규칙으로 4×8 원판 2400 × 1200 × 20 mm에 가장자리 여유 10 mm, 부재 간격 12 mm) |
| 그림 · 뒤판 | 고정틀 뒤 별도 뒤판에 붙이는 그림. 없음/있음, 크기, 여유, A4·A3·A2 단추 |
| 원판 | 목재 원판 크기와 홈 깊이. 기본 크기는 프리셋을 따릅니다(`standard_4x8_v1`은 2400 × 1200 × 20 mm, 나머지는 1220 × 900 × 20 mm). 원판을 고치지 않은 채 프리셋을 바꾸면 새 프리셋의 기본값으로 바뀌고, 고친 원판은 그대로 둡니다. 눌러서 펼칩니다 |
| 아래 단추 | 입력을 JSON 파일로 **불러오기**·**저장**, **R3 예제로 되돌리기** |

### 단문과 경첩 방향

<img src="images/design-single.png" width="280" alt="단문을 고르면 경첩 방향을 고르는 칸이 나타난다">

단문을 고르면 경첩 방향(왼쪽·오른쪽)을 고르는 칸이 나타납니다. 오른쪽을 고르면 오른쪽 선대에 경첩을, 반대쪽 선대에 손잡이와 걸쇠를 답니다. R3 프리셋은 양문 전용이므로 단문은 `standard_v1`으로 설계합니다.

### 외경과 내경

<img src="images/design-inner.png" width="280" alt="내경 기준으로 바꾸면 383 × 506이 채워지고 외경 463 × 586과의 관계가 적힌다">

**외경**은 완성된 바깥 치수, **내경**은 창짝이 들어가는 고정틀 안쪽 치수(안목)입니다. 외경 = 내경 + 2 × 40 mm(고정틀 폭)이므로 R3의 외경 463 × 586은 내경 383 × 506과 같은 창입니다. 기준을 바꾸면 같은 창이 되도록 숫자를 바꿔 넣습니다.

### 액자형(화판)

<img src="images/design-artwork.png" width="310" alt="크기 기준을 화판으로 바꾸면 화판 칸이 나타나 두께·덮는 폭·끼움 여유·스페이서를 입력한다">

크기 기준 **화판**은 창호를 그림 액자로 쓰는 형식입니다. 고정틀이 화판 가장자리를 **덮는 폭**만큼 덮으므로 외경 = 화판 − 2 × 덮는 폭 + 2 × 40 mm입니다. A2 420 × 594에 덮는 폭 8 mm이면 외경 484 × 658, 내경 404 × 578입니다.
**화판 · 액자형** 칸에 화판 두께, 덮는 폭, 끼움 여유, 스페이서를 입력합니다. 기본값은 각각 3 · 8 · 1 · 3 mm이므로 화판 크기만 넣어도 됩니다. 화판은 고정틀 뒤 한 층에서 같은 원판으로 깎은 뒤틀 4개가 잡습니다. 뒤틀 폭은 고정틀 폭에서 덮는 폭과 끼움 여유를 뺀 값이고, 그 안쪽에 화판이 네 변 끼움 여유를 두고 들어갑니다. 스페이서·뒷판·걸이 철물은 별도 조달이며 제작 전 확인 항목(PENDING)으로 남습니다.
액자형에서는 **그림 · 뒤판** 칸이 잠깁니다. 화판이 그림 자리를 대신하기 때문입니다. A3 그림을 전제로 하는 `hanok_A3_portrait_R3` 프리셋과도 함께 쓸 수 없습니다.

### 미리보기

<img src="images/design-nesting.png" width="664" alt="원판 배치 탭: 원판 한 장 위에 모든 부품이 놓이고 쓰는 범위 1091 × 284 mm가 점선으로 표시된다">

**정면도** 탭은 창을 앞에서 본 모양과 외경·내경 치수를, **원판 배치** 탭은 모든 부품을 원판 한 장에 놓은 모습을 보여 줍니다. 진한 점선은 실제로 쓰는 범위(이 예에서 1091 × 284 mm), 옅은 점선은 원판 가장자리 여유입니다.
액자형이면 정면도에 뒤틀 4개가 고정틀 뒤 한 층으로 흐리게, 화판이 파선 윤곽으로 함께 나옵니다. 원판 배치에도 뒤틀이 같은 색으로 들어갑니다.

<img src="images/design-artwork-preview.png" width="664" alt="액자형 정면도: 외경 484 × 658, 내경 404 × 578, 화판의 파선 윤곽과 고정틀 뒤의 뒤틀">

### 규칙을 어겼을 때

<img src="images/design-error.png" width="280" alt="외경 가로 600을 넣자 칸이 빨갛게 바뀌고, 외경 가로를 473 mm 이하로 줄이거나 세로를 751 mm 이상으로 늘리라는 문구가 나온다">

규칙을 어기면 해당 칸이 빨갛게 바뀌고 아래에 원인과 고치는 값이 나옵니다. 위 그림은 R3 프리셋에서 외경 가로를 600으로 넣은 경우입니다. 창짝이 너무 넓어 높이/폭이 1.96이 되었으니, 가로를 473 mm 이하로 줄이거나 세로를 751 mm 이상으로 늘리라고 알려 줍니다. 끝의 회색 글자(`leaf.aspect_ratio`)는 규칙 이름입니다.

고치는 값은 입력 하나만 바꿔 엔진에 다시 물어 찾은 값이며, 다음 규칙에서 나옵니다.

| 규칙 | 알려 주는 값 |
|---|---|
| 창살이 너무 많음 | 들어가는 최대 창살 수, 그 창살이 들어가는 최소 크기 |
| 개구부가 남지 않음 | 개구부가 생기는 최소 크기 |
| 창짝 높이/폭(R3) | 통과하는 최대 가로와 최소 세로 |
| 참고 경첩 간격 | 경첩 두 개가 들어가는 최소 세로 |
| 그림이 들어가지 않음 | 들어가는 그림 크기·여유, 그림이 들어가는 최소 크기 |
| 부품이 원판보다 큼, 원판 폭 부족 | 필요한 원판 크기와 창 크기 |
| 덮는 폭이 끼움 여유보다 작음(액자형) | 통과하는 덮는 폭과 끼움 여유 |
| 뒤틀이 창살보다 좁음(액자형) | 통과하는 덮는 폭과 끼움 여유 |
| 스페이서와 화판이 원판보다 깊음(액자형) | 통과하는 화판 두께·스페이서와 필요한 원판 두께 |

값 하나는 그 규칙만 풀므로 고친 뒤 다른 규칙이 나올 수 있습니다. 예를 들어 R3 프리셋은 외경 세로 586 mm에서 가로 463~473 mm만 A3 그림과 창짝 높이/폭을 함께 통과합니다.

### 패키지 생성

<img src="images/design-summary.png" width="310" alt="요약: 사전 확인 통과 표시, 치수 목록, 원판 사용 막대, 같은 설계 패키지 알림, 패키지 생성 단추">

오른쪽 요약에는 해석한 치수(외경·내경·창짝·개구부·빈칸), 부품·홈·도그본·결합쌍 수, 원판 사용량이 나옵니다. **사전 확인 통과 · 도면 검사 전**은 규칙과 원판 배치를 통과했다는 뜻이고, 홈끼리 붙는지 같은 판정은 아직 하지 않은 상태입니다.

**패키지 생성**을 누르면 DXF를 저장해 다시 읽고, 검사 71개를 모두 통과한 경우에만 패키지를 저장합니다. 보통 2초 안팎이 걸리고, 끝나면 그 패키지 화면으로 넘어갑니다. 같은 설계의 패키지가 이미 있으면 그림처럼 알려 주고 **패키지 열기**와 **ZIP 받기**를 바로 보여 줍니다. 같은 실행 환경(OS, 글꼴, Python과 라이브러리 버전)에서는 같은 입력이 언제나 같은 패키지 ID가 되며, 이미 있는 패키지를 덮어쓰지 않습니다. 다른 컴퓨터에서 만든 패키지와 같은 설계인지는 revision으로 봅니다.

### 생성 단계에서 실패하면

<img src="images/build-failed.png" width="310" alt="결과 카드: 도면 검사 71개 중 1개 실패, 이웃한 두 홈이 붙는다는 설명과 작업 기록 경로">

사전 확인을 통과해도 저장한 DXF를 검사하는 단계에서 떨어질 수 있습니다. 그림은 창살을 세로 9 · 가로 30으로 늘린 경우입니다. 빈칸이 4.52 mm인데 이웃한 두 홈의 도그본 반지름을 더하면 6.4 mm가 필요해서 홈끼리 붙는다고 알려 줍니다. 실패하면 패키지를 저장하지 않고 실패한 검사와 이유, 작업 기록 파일(`output/failures/…`)을 보여 줍니다. 입력은 그대로 남아 있으니 창살 수를 줄여 다시 생성합니다.

## 기록과 패키지 화면

### 기록

<img src="images/history.png" width="960" alt="기록 화면: 만든 패키지 5개가 최신순으로 나오고 각 줄에 열기와 불러오기가 있다">

위쪽 **기록**을 누르면 `output/`에 만든 패키지가 최신순으로 나옵니다. **열기**는 패키지 화면을, **불러오기**는 그 패키지의 입력을 설계 화면에 채웁니다. 마지막으로 만든 패키지에는 **최신**이 붙습니다.

### 패키지 화면

**내려받기**에서는 전체 ZIP(새 패키지는 파일 38개와 매니페스트, 모두 39개)을 받거나 파일을 하나씩 받습니다. 보내기 전에 매니페스트의 해시와 대조하므로, 패키지가 만들어진 뒤 바뀐 파일은 내려받을 수 없습니다. 위 화면은 출력 형식 등록 모듈을 추가하기 전의 파일 37개 패키지이며, 기존 패키지는 당시 파일 목록과 개수를 그대로 표시합니다. 새 모듈도 재생성용 소스에 들어가므로 파일 하나와 패키지 ID가 달라지지만 검사 71개는 같습니다.

DWG를 다시 DXF로 되돌리면 부재 번호와 레이어·선 종류가 남아 검사 71개를 그대로 통과합니다.

## 명령줄로 쓰기

웹 화면 없이 터미널에서도 같은 패키지를 만듭니다.

```bash
.venv/bin/hanok-window build --input examples/double_r3.json --output output      # 예제 입력으로 만들기
.venv/bin/hanok-window build --type double --size 600x800 --lattice 2x4 --output output
.venv/bin/hanok-window resolve --type single --hinge-side right --size 420x900 --lattice 2x6   # 사전 확인만
.venv/bin/hanok-window verify output/packages/<패키지 ID>                               # 파일 해시 대조
```

`--input`으로 준 JSON은 웹 화면에서 저장한 JSON과 같은 형식이라, 같은 입력이면 웹과 패키지 ID가 같습니다. `--size 463x586`처럼 옵션으로 준 크기는 실수(463.0)로 기록되어 revision은 같아도 패키지 ID가 다릅니다. 모든 옵션은 [생성기 README의 명령줄](../../README.md#명령줄)에 있습니다.

## 문제 해결

| 이런 문구나 증상이 보이면 | 이렇게 합니다 |
|---|---|
| `가상환경(.venv)이 없습니다` | generator 폴더에서 [설치](#설치)의 2~4번을 합니다 |
| `127.0.0.1:8765에서 이미 다른 서버가 응답합니다` | 직접 켠 서버라면 그 터미널에서 Ctrl+C로 끄고, 아니면 `./web.sh start --port 8800`처럼 다른 포트로 켭니다 |
| `켜져 있지만 응답하지 않습니다` | `./web.sh log`로 서버 기록의 마지막 줄을 보고 `./web.sh restart`로 다시 켭니다 |
| `브라우저를 열지 못했습니다` | 브라우저 주소 창에 http://127.0.0.1:8765 를 직접 넣습니다 |
| macOS가 `web-start.command`를 열지 않음 | 인터넷에서 받은 ZIP을 풀어 쓰는 경우입니다. 시스템 설정 › 개인정보 보호 및 보안에서 **그래도 열기**를 누르거나 터미널에서 `./web.sh start`를 씁니다 |
| 입력 칸이 빨갛게 바뀜 | 칸 아래 문구의 값으로 고칩니다([규칙을 어겼을 때](#규칙을-어겼을-때)) |
| 생성이 도면 검사에서 실패 | 결과 카드의 이유대로 창살 수나 크기를 바꿉니다. 작업 기록은 `output/failures/`에 남습니다 |
| 화면의 버전 표시가 예전 그대로 | 새 버전을 받은 뒤 `.venv/bin/python -m pip install -e .`를 다시 합니다 |

## 그림 다시 만들기

화면이 바뀌면 이 폴더의 `make_images.py`로 그림을 다시 만듭니다. [설치](#설치)를 마친 Python 가상환경과 Chrome 또는 Chromium이 필요합니다. 예제 5종을 임시 폴더에 만들고 헤드리스 브라우저로 화면 15장과 축소 도면 5장을 생성하므로 실제 `output/`은 건드리지 않습니다.

저장소 뿌리에서 **Windows PowerShell**로 실행합니다.

```powershell
cd generator
.\.venv\Scripts\python.exe docs/manual/make_images.py
.\.venv\Scripts\python.exe docs/manual/make_images.py --check
```

**macOS·Linux**에서는 다음 명령을 씁니다.

```bash
cd generator
.venv/bin/python docs/manual/make_images.py
.venv/bin/python docs/manual/make_images.py --check
```

이미 `generator/`에 있다면 `cd generator`는 생략합니다. 일반 실행은 20장 모두 촬영한 뒤 `docs/manual/images/`에 덮어씁니다. 촬영 도중 실패하면 기존 그림을 보존합니다. 다른 폴더에 먼저 찍어 검토하려면 `--out "그림 폴더"`를 붙입니다.

`--check`는 새 그림을 임시 폴더에 만들고 기준 폴더와 **크기·RGBA 픽셀**을 비교합니다. PNG 부가 정보나 압축 방식만 달라진 것은 차이로 세지 않습니다. 기준 폴더는 기본 `docs/manual/images/`이고 `--out`으로 바꿀 수 있습니다. 검사 중에는 기준 파일을 만들거나 덮어쓰거나 지우지 않습니다.

| 종료 코드 | 뜻 |
|---|---|
| `0` | 일반 생성 완료 또는 그림 20장이 모두 같음 |
| `1` | 그림의 크기·픽셀 차이, 기준 그림 누락·추가 PNG, 또는 기준 폴더 없음 |
| `2` | 브라우저 실행·촬영 실패, 읽을 수 없는 그림, 잘못된 옵션 등 실행 오류 |

차이가 있으면 파일명과 이유를 출력합니다. 먼저 같은 촬영 환경인지 확인하고, 화면 변경에 따른 차이면 새 그림의 글자·잘린 영역·오류 설명을 살펴본 뒤 기준 그림을 갱신합니다. 그림을 바꾼 경우 이 문서의 대체 설명과 촬영 환경도 함께 고칩니다. **같음은 기준 그림과의 일치이며 화면 내용이 올바르다는 자동 판정은 아닙니다.**

브라우저는 `--chrome`으로 지정한 실행 파일을 우선합니다. 지정하지 않으면 macOS의 기본 Chrome 앱, `PATH`의 Chrome·Chromium 이름, Windows 설치 폴더 순으로 찾습니다. Windows에서는 `%ProgramFiles%`, `%ProgramFiles(x86)%`, `%LOCALAPPDATA%` 아래의 `Google\Chrome\Application\chrome.exe`를 확인하며 앞의 두 환경 변수가 비어 있으면 표준 `C:\Program Files`와 `C:\Program Files (x86)` 경로를 사용합니다. 지정한 실행 파일이 없으면 다른 브라우저로 바꾸지 않고 오류를 냅니다. 경로에 공백이 있으면 따옴표로 감쌉니다.

```powershell
.\.venv\Scripts\python.exe docs/manual/make_images.py --check --chrome "C:\Program Files\Google\Chrome\Application\chrome.exe"
```

```bash
.venv/bin/python docs/manual/make_images.py --check --chrome "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
.venv/bin/python docs/manual/make_images.py --check --chrome "/usr/bin/chromium"
```

반복 촬영을 위해 임시 예제 폴더의 생성 시각은 2026-09-17 09:00~09:04 KST, 실패 카드의 시간은 `0.0초`, 기록 이름은 `failures/example.json`으로 고정합니다. 기록 화면의 임시 출력 경로도 예시 경로로 바꿉니다. 이 값들은 설명용이며 실제 실행 시간이나 작업 기록이 아닙니다. 오류 내용·검사 수·파일 수·패키지 ID는 실제 결과를 보여 줍니다. 부분 그림을 찍는 동안에만 상단 메뉴의 고정을 풀어 내용이 가리지 않게 합니다. 실제 프로그램과 패키지 내용은 바꾸지 않습니다.

촬영 기준은 **Windows 11 Pro 10.0.26200, Chrome 151.0.7922.176, CPython 3.11.9, `requirements.lock`의 실행 의존성(Pillow 12.3.0 포함), ODA File Converter 27.1.0 설치 상태**입니다. 화면은 Noto Sans KR·Consolas, 도면은 Arial을 사용했습니다. 화면 크기는 1280×1000 CSS 픽셀, 배율 2, 밝은 테마, 시간대 Asia/Seoul입니다. 운영체제·글꼴·Chrome·Python·의존성·ODA 설치 상태가 다르면 화면이 바뀌지 않아도 그림이 달라질 수 있으므로 운영체제 사이의 픽셀 일치를 보장하지 않습니다.

CI는 브라우저 없이 경로 탐색·픽셀 비교·기준 파일 보존·자원 정리 시험을 세 운영체제에서 실행합니다. 실제 그림 최신 여부는 위 명령으로 필요할 때 확인합니다. 현재 기준 그림의 실제 촬영과 반복 비교는 Windows에서 검증했습니다.
